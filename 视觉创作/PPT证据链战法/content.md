## P1 · 现象 / 痛点

- **标题**：AI 做 PPT 的翻车现场
- **副标**：页多但空 · 结论无支撑 · 视觉华丽却站不住
- **章节类型**：现象 / 痛点
- **核心主张**：AI 生成的 PPT 常见三类病——空、虚、飘，不是不会画，是不会"立论"
- **关键要点**：
  - 空：一页就一句口号，撑不起一个观点，翻完像没看
  - 虚：结论直接拍出来，没有数据 / 案例 / 出处背书，读者无从信
  - 飘：视觉很炫，但和要讲的事没关系，华而不实
- **数据 / 数字**：3 类病（空 / 虚 / 飘）
- **金句**：PPT 不是排版比赛，是说服工程

---

## P2 · 诊断 / 根因

- **标题**：病根不在工具，在顺序
- **副标**："先画图后找理由"——把证据链排在视觉之后
- **章节类型**：诊断 / 根因
- **核心主张**：翻车不是因为 AI 不会画，而是人把"找理由"排在"画图"之后，证据链缺失
- **关键要点**：
  - 传统做法：选风格 → 出图 → 往图里塞字 → 发现没话讲就硬凑
  - 结果是"为排版而排版"，每一页先有壳、后找魂
  - 真正的瓶颈是内容组织（立论），不是图像生成能力
- **数据 / 数字**：1 个错序（画图 > 证据）
- **金句**：先有壳后找魂，魂永远凑不齐

---

## P3 · 原理 / 方法论

- **标题**：CyberPPT 三段式
- **副标**：段1 证据链 → 段2 视觉蓝图 → 段3 PPTX 重建
- **章节类型**：原理 / 方法论
- **核心主张**：把"立论"前置成显式三段，每段有入口产物，前一段不过关不进下一段
- **关键要点**：
  - 段1 证据链：每页先写"这页凭什么成立"，而非先想配色
  - 段2 视觉蓝图：证据齐了再选 layout、填 props，让视觉服务论证
  - 段3 PPTX 重建：浏览器里改稿、导出真正可编辑的 PPTX
  - 核心原则：先过"证据关"再进"视觉关"
- **数据 / 数字**：3 段式 · 2 关（证据关 / 视觉关）
- **金句**：证据关不过，视觉关再美也白搭

## P4 · 解法 / 操作（段1 证据链怎么写）

- **标题**：段1 · 怎么写证据链
- **副标**：每页 conclusion + evidence_ids + conflicts 三件套
- **章节类型**：解法 / 操作
- **核心主张**：证据链不是一段话，而是每页结构化字段——让"凭什么成立"可被机器检查
- **关键要点**：
  - slides[].evidence.conclusion：用一句话写清"这页凭什么成立"
  - evidence_ids[]：引用 text 字段里的数据 key，结论必须能指回证据
  - conflicts[]：列出需回避或说明的矛盾（可选，但高管场景必填）
  - 自检：某页说不出 conclusion，就先补 evidence 再选 layout
- **数据 / 数字**：3 件套（conclusion / evidence_ids / conflicts）
- **金句**：结论能指回证据，才算立住了

---

## P5 · 进阶 / 纪律（段2+段3 + 反模式）

- **标题**：段2 选 layout · 段3 编辑导出 + 反模式
- **副标**：视觉为论证服务；别跳过选风格、别给图标页码
- **章节类型**：进阶 / 纪律
- **核心主张**：段2 让视觉蓝图紧贴证据，段3 在浏览器改稿导出；同时守住两条反模式纪律
- **关键要点**：
  - 段2：layout:query 选页 → inspect:layout + props:safe 填 props → render_goal_deck.sh 出 HTML
  - 段3：控制台改稿（文字 / 布局 / 图表 / 配色）→ 导出 PPTX / PDF / 单文件 HTML
  - 反模式①：不要跳过选风格——必须先问用户、展示主题预览、确认后再生成
  - 反模式②：讲解图不要出现 P1/P2 页码标记，页码只在 PDF 合成时标
- **数据 / 数字**：2 段操作 · 2 条反模式
- **金句**：风格是用户的，不是你的默认审美

## P6 · 收束 / 速查

- **标题**：三段式速查卡
- **副标**：证据三件套随身，两关两反模式记牢
- **章节类型**：收束 / 速查
- **核心主张**：把"先证据后视觉"焊进肌肉记忆，AI PPT 质量立刻上一个台阶
- **关键要点**：
  - 段1 证据链：每页 conclusion + evidence_ids + conflicts（先过证据关）
  - 段2 视觉蓝图：先选 layout 再填 props（视觉为论证服务）
  - 段3 PPTX 重建：浏览器改稿 → 导出可编辑 PPTX
  - 两反模式：不跳过选风格 / 讲解图不标页码
- **数据 / 数字**：3 段 · 3 件套 · 2 反模式
- **金句**：顺序对了，AI 才是你的搭档不是你的甲方
