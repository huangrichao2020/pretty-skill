## P0 · 封面

- **章节类型**：封面
- **核心主张**：小工具的本质 = 知识的网页讲解版。9 宫格解决不了的"7 天行程讲不清"，用双维选择 + 路径地图 + 风格色主题的 H5 解决。
- **关键要点**：
  - 双维选择：天数（2/3/4 天）× 节奏（特种兵/正常/休闲）= 9 条攻略线
  - 路径地图：AI 水墨底图 + 绝对定位圆点 + SVG 贝塞尔曲线
  - 风格色主题：CSS 变量联动 banner / 路径 / 时间轴
- **金句**：**折叠是 9 宫格，展开是 H5 小工具**。9 宫格讲不清 7 天行程，因为它是折叠；H5 是展开。

## P1 · 痛点 + 洞察（运营阶段 0 · 信号研究）

- **章节类型**：钩子（开篇戳痛）
- **核心主张**：小红书原生格式有 3 个解决不了的内容痛，小工具正好填补。
- **认知锚点**：
  - **画面**：9 宫格塞 7 天行程，像把一周的衣服塞进一个行李箱——关不上
  - **反差**：游客看到的是"我去过"列表，攻略读者想要的是"我该按什么节奏走"
- **关键要点**：
  - 痛点 1：攻略太长 → 9 宫格讲不清 7 天行程
  - 痛点 2：心得太散 → 没法对比、没法锚定关键节点
  - 痛点 3：笔记太碎 → 看完不知道下一步
  - 洞察：小工具 = 知识的"网页化"载体
- **金句**：**9 宫格是折叠，H5 是展开。攻略要展开讲，才讲得清。**

### P1.5 · 信号研究动作（v2 新增 · 阶段 0）

**为什么要在 P1 后面插这一步**：没有信号池，标题凭感觉发，评论区没争议

**3 步抓信号**：
1. **平台侧**：小红书首页前 10-20 条同题材高互动内容，记录 `title / hook / angle / 结构标签 / 评论信号 / CTA / 标签组`
2. **需求侧**：评论区抓"支持/反对/中性"三组观点 → 找可发争议点
3. **跨平台**：web_search 综合 60+ 攻略 → 去广告 + 数据交叉

**杭州烟雨 v1 实战回填**（v2 补）：
- 搜"杭州攻略 2 天 1 晚"小红书首页 → 20 条候选池
- 抓评论区争议点：「特种兵值不值」「休闲花销真不真」「西湖要不要环湖」
- web_search 60+ 篇攻略综合 → 7 步、9 步、特种兵 3 万步的版本

**量化疗效**：1 个城市 30 分钟出信号池，vs 拍脑袋写

## P2 · 方法论（双维选择 · 运营阶段 1 · 账号定位）

- **章节类型**：核心解法
- **核心主张**：攻略类 H5 的核心交互 = **双维选择**（天数 × 节奏），让用户 1 步锁定自己的玩法
- **认知锚点**：
  - **画面**：餐厅菜单 + 自助餐台 — 选份量 × 选菜系 = 你的套餐
  - **隐喻**：H5 是菜单，9 条攻略线是套餐
- **关键要点**：
  - 横轴（天数）= 1 个变量 × 3 档（2/3/4 天）
  - 纵轴（节奏）= 1 个变量 × 3 档（特种兵/正常/休闲）
  - 笛卡尔积 = 3 × 3 = 9 条攻略线
  - 每条攻略线带：步数 / 预算 / 适合人群 + 每日时间轴
- **数据/数字**：
  - 9 条攻略线 × 7 个景点 = 63 个核心 POI
  - 用户切换 9 次 plan，每次 < 1s 响应
- **金句**：**1 次双维选择 = 9 份定制攻略。折叠成菜单，展开就是大餐。**

### P2.5 · 4 变量账号定位（v2 新增 · 阶段 1）

| 变量 | 杭州烟雨 v1 实例 |
|---|---|
| 目标用户 | 周末 2-3 天出游 / 自由行 / 选节奏困难症 |
| 内容价值主张 | 9 条现成攻略 + 路径地图，开包即用 |
| 差异化角度 | 双维选择（天数×节奏）笛卡尔积，不只做 1 套 |
| 风格规范 | 短句 + 数据 + 数字 + 不剧透（涉及隐私内容） |

**输出**：

- 红线清单（剧透 / 人身攻击 / 虚假承诺）

## P3 · 节奏差异（3 档 · 运营阶段 2 · 选题评分）

- **章节类型**：深化（核心解法 2）
- **核心主张**：3 档节奏的核心差异不是"快慢"，而是"用户状态"——时间紧 / 体验 / 慢生活
- **认知锚点**：
  - **画面**：3 种跑步姿势——冲刺跑 / 配速跑 / 散步
  - **输入输出**：输入=时间预算，输出=行程密度
- **关键要点**：

| 节奏 | 日均步数 | 日预算 | 核心动作 | 排除动作 |
|---|---|---|---|---|
| 🟠 特种兵 | 2.5-3.5 万 | ¥300-400 | 早 6:30 起 / 共享单车 / 5-7 点 | 进茶馆 / 馆藏 |
| 🟢 正常 | 1.5-2 万 | ¥500-600 | 8 点起 / 1 船游 + 1 登塔 + 1 茶馆 | 特种兵暴走 |
| 🔵 休闲 | 0.6-1.2 万 | ¥900-1500 | 9 点后起 / 骑行 / 1 茶馆 2h+ | 抢时间打卡 |

- **金句**：**节奏不是快慢，是用户状态。特种兵要"值回票价"，休闲要"我值不值得慢下来"。**

### P3.5 · 5 维选题评分（v2 新增 · 阶段 2）

**5 维**（每维 0-2 分）：

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 热度信号 | 没数据 | 30+ 攻略提到 | 60+ 攻略 + 评论区争议 |
| 账号匹配 | 完全不沾边 | 部分匹配 | 完美匹配 4 变量 |
| 互动潜力 | 无互动钩子 | 1 个问句 | 站队 + 选择 + 经验 3 钩子 |
| 可写性 | 信息缺口大 | 1-2 个待查 | 全部现成 |
| 风险分 | 极高（必踩线）| 中等（可绕）| 低（安全）|

**总分规则**：
- ≥ 6 分：可发
- 7-8 分：强发
- ≥ 9 分：必爆（信号强 + 完美匹配）
- 风险分 ≥ 2：直接淘汰

**杭州烟雨 v1 实战回填**（v2 补）：
- 选题"小工具内测第一天" = 蹭热点（星爷路演）+ 稀缺感（第一款攻略 H5）+ CTA（一键三连）
- 评分：热度 2 / 匹配 2 / 互动 2 / 可写 2 / 风险 0 = **8 分（强发）**

## P4 · 路径地图（AI 底图 + overlay · 运营阶段 3 · 视觉包装）

- **章节类型**：深化（视觉重玩法）
- **核心主张**：路径地图 = AI 真实地理底图 + 绝对定位圆点 + 贝塞尔曲线，**比 SVG 画底图强 10 倍**
- **认知锚点**：
  - **画面**：地铁线路图 — 真实地理 + 圆点站 + 折线
  - **转折**：从"代码画地图"到"AI 出图当地图"
- **关键要点**：
  - 底图 1 张：matrix 生水墨手绘地图（含真实山/水/桥/建筑）
  - 11 个景点用 `%` 绝对定位（断桥/三潭/雷峰/西湖/灵隐/龙井/九溪/满觉陇/西溪/河坊/拱宸）
  - 当前 plan 路径用 SVG 贝塞尔曲线，2.5s 描边动画
  - 描边后 1.5s 持续虚线流动（dashFlow）
  - 白色光点沿路径无限循环跑
  - 起点绿色"起" / 终点红色"终" 圆角胶囊
- **数据/数字**：
  - 路径粗细：14px 白边 + 7px 彩色（双层）
  - viewBox: 1600×900（真实像素感）
  - walker 半径: 8px（带阴影发光）
- **金句**：**让 AI 当画家，让 SVG 当舞台。底图 AI 出，路径 SVG 画。**

### P4.5 · 视觉包装 4 子任务（v2 新增 · 阶段 3）

1. **封面**：主文案 + 副文案 + 1 条生图 prompt（高文字可读）
2. **配图**：3-6 张图解文案 + 对应 prompt
3. **路径地图**：AI 真实地理底图 + 绝对定位圆点 + SVG 贝塞尔曲线
4. **风格色主题**：CSS 变量 + body[data-style] 联动全站

**杭州烟雨 v1 实战数据**：
- 9 张景点（matrix 16:9）+ 1 张水墨底图 + 1 张雷峰塔 logo
- 路径 11 个 POI × 3 节奏颜色 = 33 个绝对定位点
- 14px 白边 + 7px 彩色双层描边
- 2.5s 描边 + 1.5s 虚线流动 + 8px 光点

**v2 升级提示**：源图分辨率 ≥ 2K（2048×1152），避免小红书发图压缩失真

## P5 · 风格色主题联动（运营阶段 3 续 · 视觉包装）

- **章节类型**：深化（动效 + 视觉）
- **核心主张**：CSS 变量 + body[data-style] = 切风格切全站色调，无 JS 改色
- **认知锚点**：
  - **画面**：调色盘 — 切 1 个主色，整张画变调
  - **隐喻**：CSS 变量 = 中央调色台，所有元素 = 调色板引用者
- **关键要点**：

```css
:root { --style-color: #4a9b6e; }
body[data-style="特种兵"] { --style-color: #e87b3e; }
body[data-style="正常"] { --style-color: #4a9b6e; }
body[data-style="休闲"] { --style-color: #5b8db8; }
```

切风格时联动：
- banner 渐变背景
- tab 选中色
- 路径颜色
- 时间轴胶囊
- 数字色
- 滑块 thumb
- 滚动条

- **金句**：**1 个 CSS 变量 = 整站调色。颜色不是装饰，是信息层级。**

## P6 · 工具链 + 打包规范（运营阶段 4 · 评分检查 + 阶段 5 · 发布清单）

- **章节类型**：深化（实操）
- **核心主张**：用 AI 生图 + 缩图 + 离线打包 3 步，把 40MB 原始资源压成 1.8MB 离线 zip
- **认知锚点**：
  - **画面**：原始食材 → 切配装盘 — 9 张 2K 图 → 9 张 1K jpg
  - **隐喻**：打包 = 烹饪的最后一步（生料→成品）
- **关键要点**：

```bash
# 1. 缩图 + 转 jpeg
sips -s format jpeg -s formatOptions 80 -Z 1000 img/01.png --out img/01.jpg

# 2. 校验（minitool-zip-builder SKILL.md）
grep -c "内联 <script>" index.html  # 必须 0

# 3. 打包（cd 进目录再压内容）
cd hangzhou-tool && zip -r ~/Desktop/xxx.zip . -x '*.DS_Store'
```

**硬性约束**（minitool-zip-builder 规范）：
- 总包 < 2MB
- 单图 < 500KB
- 脚本全部外置
- 资源全部本地
- 无 iframe / base / 自建 CSP

- **金句**：**40MB 原始 → 1.8MB 离线 = 压 95% 体积。AI 生图不是堆，是筛选。**
