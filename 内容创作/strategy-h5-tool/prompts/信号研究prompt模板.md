# 信号研究 Prompt 模板（v2 新增 · 运营阶段 0）

> 装 xhs-ops 后的核心工作流 — 抓首页推荐流前 10-20 条 → 提取可复用结构

---

## 目标

从平台侧 + 需求侧 + 跨平台抓"30+ 条同题材高互动内容"，沉淀 3-5 个标题骨架 + 封面层级模板，下个城市 30 分钟出信号池

---

## 输入模板

```yaml
target_city: <城市>
target_topic: <主题，如"2 天 1 晚攻略">
platform: ["小红书", "抖音", "公众号", "知乎"]
sample_size: 10-20
time_window: "近 30 天"
exclude_topics: ["广告", "探店打卡"]
```

---

## 步骤 1：平台侧抓取（小红书首页）

**Prompt 模板**（给 web_search / 浏览器自动化用）：

```
抓小红书首页推荐流前 20 条 <主题> 相关内容，记录以下字段：

1. title（标题原文）
2. hook（首屏钩子 / 摘要）
3. cover_text（封面主文案）
4. cover_type（图文 / 视频 / 文字配图 / 长文）
5. account_type（达人 / 普通用户 / 品牌 / 垂类号）
6. likes / comments / collects（如可见）
7. tags（话题 / 标签 / 关键词）
8. cta（评论区引导词 / 互动动作）
9. reason_to_stop（为什么会点开或停留）

输出格式：JSON 或 Markdown 表格（20 条）

约束：
- 不要广告
- 不要重复主题（保留 2-3 条同主题用于判断推荐偏好）
- 优先高互动（点赞 > 1000）
```

**杭州烟雨 v1 实战回填**（v2 补）：
- 关键词："杭州攻略 2 天 1 晚"
- 抓 20 条 → 平均点赞 3500，Top 1 点赞 1.2w
- 标题骨架 3 个：
  - "杭州 X 天 Y 晚，人均 Z 元超详细攻略"
  - "在杭州被 X 个细节戳到了"
  - "杭州 X 天 Y 晚，我踩了 N 个坑"

---

## 步骤 2：评论区抓取（争议点信号）

**Prompt 模板**：

```
抓小红书 <关键词> 搜索结果前 10 条笔记的评论区，每条抓两批：
1. 热门 Top 10（按点赞排）
2. 最新 Top 10（按时间排）

提取字段：
- user（用户）
- time（时间）
- text（评论文本）
- likes（点赞数）
- replies（回复数）

输出 3 类观点：
- 支持型（点赞 ≥ 10，观点明确）
- 反对型（点赞 ≥ 5，反驳/质疑）
- 中性补充（事实信息、补充体验）

约束：
- 过滤广告 / 引流
- 优先"信息密度高"的评论（短句、长信息量）
```

**杭州烟雨 v1 实战回填**（v2 补）：
- 评论区争议点 3 个：
  - "特种兵值不值"（支持/反对比 7:3）
  - "休闲花销真不真"（质疑 800+ 日均）
  - "西湖要不要环湖"（体验派/效率派分歧）

---

## 步骤 3：跨平台综合（60+ 攻略去广告）

**Prompt 模板**（给 web_search）：

```
搜索 "<城市> 攻略 <天数>天<夜数>晚 <主题>"，综合 60+ 篇攻略。

输出 4 类信息：
1. 核心景点 Top 11（按出现频次排序）
2. 每日时间轴模板（3 档节奏：特种兵/正常/休闲）
3. 预算分布（日均 ¥300-1500）
4. 关键决策点（交通/住宿/餐饮的选择题）

约束：
- 排除广告 / 探店
- 排除非自由行（团队游 / 高端定制）
- 优先 2025-2026 新攻略（数据新鲜）
- 优先数据交叉 ≥ 3 篇都提到的景点
```

**杭州烟雨 v1 实战回填**（v2 补）：
- web_search 60+ 篇攻略综合
- 11 个核心 POI（断桥/三潭/雷峰/西湖/灵隐/龙井/九溪/满觉陇/西溪/河坊/拱宸）
- 3 档节奏数据：特种兵日均 3 万步 / 正常 1.5 万 / 休闲 1 万
- 预算数据：日均 ¥300-1500 区间分布
