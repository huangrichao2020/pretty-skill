## P0 · 封面

- **章节类型**：封面
- **核心主张**：读文档不该用复制粘贴 · doc-reader 把 Office + PDF 转成纯文本 + 保留结构 + 提取关键信息
- **认知锚点**：「文档阅读 5 步漏斗」—— 读-抽-概-问-用
- **关键要点**：

  - 输出：纯文本 + 表格 + 图片 + 元数据

## P1 · 痛点 · 读文档的 4 个常见错误

- **章节类型**：钩子
- **核心主张**：4 个常见错误让文档信息丢失 50%+
- **认知锚点**：「4 大读文档陷阱」—— 死读/无结构/不复盘/不输出
- **关键要点**：
  - 错误 1：复制粘贴 → 格式破坏 / 表格错位
  - 错误 2：用 OCR 工具 → 文本型 PDF 不需要 OCR
  - 错误 3：忽略图片 → 30% 内容在图里
  - 错误 4：丢元数据 → 后续引用找不到源头
- **金句**：读文档不是搬文字，是搬结构

- **章节类型**：核心解法
- **核心主张**：5 项能力缺一不可 · 才是"完整提取"
- **认知锚点**：「5 项提取能力雷达」—— 表格/图表/公式/章节/作者

## P3 · 工作流（4 步）

- **章节类型**：核心解法
- **核心主张**：识别格式 → 选择工具 → 提取 → 验证
- **认知锚点**：「4 步工作流传送带」—— 读-抽-概-用
- **关键要点**：
  - Step 1：识别格式（DOCX/XLSX/PDF）
  - Step 2：选择工具（python-docx / openpyxl / pdfplumber）
  - Step 3：分块提取（文本 / 表格 / 图片 / 元数据）
  - Step 4：合并 + 验证（结构完整 + 内容可读）
- **金句**：识别 → 选工具 → 提取 → 验证

---

## P4 · 与同类工具对比

- **章节类型**：深化
- **核心主张**：doc-reader vs OCR vs markdown-converter = 3 个不同定位
- **认知锚点**：「同类工具对比表」—— pdf-reader/markdown-converter/OCR
- **关键要点**：
  - doc-reader：结构化文档（DOCX/XLSX/PDF）→ 纯文本 + 结构
  - OCR：扫描件 / 图片 → 文字（慢 + 准确率 80-90%）
  - markdown-converter：任意格式 → markdown（覆盖广但精度低）
  - 三者互补，按场景选择
- **金句**：按场景选工具，不要一招鲜
