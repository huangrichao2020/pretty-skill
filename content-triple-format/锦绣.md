# 锦绣范式 · Jinxiu v3.3

> ### 💎 核心金句
>
> **大量优秀的 skill 或知识做出来，没人用，因为没人看得懂。**
>
> **锦绣 = 多花 5 分钟，生成能讲解清楚你的 skill 或知识的图片、封面、pptx、html，方便人看和学**。
>
> 项目**从不追求快速生成 SOP**。**清晰 > 速度**。

> **TL;DR**：**锦绣 = 任何 skill 创建时自动生成的 3 样传播素材**。
> 1. **2 张封面**（横屏 + 竖屏）
> 2. **8-12 张讲解图**（creator 自行决定）
> 3. **1 份融合 md**（公众号 + 自媒体稿 + AI 阅读 三用）
>
> **不限定发哪个平台**——creator 拿到素材后自己决定发朋友圈/小红书/抖音/推特/微博/...随便。

## 💡 为什么需要"锦绣"

> **大量优秀的 skill 或知识做出来，没人用，因为没人看得懂。**

### 3F Content 解决了什么 + 没解决什么

| 范式 | 服务对象 | 解决了什么 | 没解决什么 |
|---|---|---|---|
| **3F Content**（v1-v2）| **AI** | AI 能直接消化（.md 喂 LLM）| ❌ 给人看 = 文字 PPT（丑）|
| **锦绣**（v3 新增）| **人** | 一眼懂 + 视觉冲击 + 易传播 | ❌ 不能被 AI 消费（视觉是给人的）|

**3F Content + 锦绣 = AI 友好 + 人易传播 = 完整闭环**。

### 项目哲学（v3.3 核心金句）

> **清晰 > 速度** · **让人看得懂 > 快速生成**

之前的 AI 工具追求"自动化"和"快速生成"——但**优秀知识没人用的根因就是没人看得懂**。

**锦绣 = 让人真正看懂 = 多花 5 分钟生成能讲解清楚的图片、封面、pptx、html**。

### 为什么不限定平台

之前的 v3.0 设计把锦绣按"平台"切（朋友圈 / 小红书 / 公众号 / 视频脚本）—— 锁死了 platform 列表。新平台出现就过时。

**v3.1 简化**：按"**形式**"切（横屏 / 竖屏 / 讲解图 / md）—— creator 拿到素材后**自己决定发哪**。

- 横屏封面 → 朋友圈 / 推特 / 微博 / 视频封面
- 竖屏封面 → 小红书 / Instagram / 抖音 / 视频号
- 8-12 张讲解图 → PPT / 公众号 / 知乎 / 视频 / 海报 / ...
- 1 份 md → 直接发公众号 + 当自媒体讲解稿 + AI 阅读

## 📐 锦绣 3 样素材（v3.1 简化版）

```
锦绣/
├── cover-横屏.png       # 1 张横屏封面（16:9 · 1920×1080）
├── cover-竖屏.png       # 1 张竖屏封面（3:4 · 1080×1440）
├── slides/              # 8-12 张讲解图（16:9 · creator 自行决定）
│   ├── slide-1.png
│   ├── slide-2.png
│   └── ...
└── readme.md            # 1 份融合 md（公众号 + 自媒体稿 + AI 阅读）
```

**总量**：10-14 个文件（2 封面 + 8-12 讲解图 + 1 md）

## 📄 3 样素材的详细规范

### 素材 1 · 横屏封面（cover-横屏.png）

**规格**：16:9（1920×1080）  
**用途**：朋友圈 / 推特 / 微博 / 视频封面 / 公众号题图

**元素**：
- 大标题（30% 画面）
- 视觉冲击元素（图标 / 抽象图形）
- 1 句话总结（20% 画面）
- 作者 / 来源水印（5% 画面）
- 大量留白（呼吸感）

### 素材 2 · 竖屏封面（cover-竖屏.png）

**规格**：3:4（1080×1440）或 9:16（1080×1920）  
**用途**：小红书 / Instagram / 抖音 / 视频号

**元素**：
- 大标题（顶部 30% 区域）
- 视觉冲击元素（中部）
- 1 句话总结（中部）
- 作者 / 来源水印（底部 5%）
- 上下大量留白

### 素材 3 · 讲解图集（slides/，8-12 张）

**规格**：16:9（1920×1080）  
**数量**：**8-12 张**（creator 自行决定，超过或低于不通过 check-3f.py）

**每张图结构**：
- 1 个核心观点（30% 画面）
- 视觉化元素（图标 / 抽象 / 数据图）
- 1 句话标题
- 不需要长正文（正文本里在 md 里讲）

**数量决策**：
- 简单知识：8 张
- 复杂方法论：10 张
- 系统性框架：12 张

### 素材 4 · 融合 readme.md（1 份）

**这是关键创新** —— 1 份 md 同时服务 3 个场景：

```markdown
# {案例标题}

> **作者**：@xxx
> **领域**：xxx
> **风格**：xxx
> **页数**：8-12 张讲解图 + 2 封面

---

## 导语（公众号开头 · 自媒体稿开头）

{1-2 段导语，口语化}
- 直接发公众号 = 这段当开头
- 自媒体稿 = 这段当"今天讲..."开头
- AI 提取要点 = 这段是关键

> **核心要点**（AI 友好 · 1 屏可读）：
> - 要点 1
> - 要点 2
> - 要点 3
> - 要点 4

---

## 第 1 章 · {章节名}

> **公众号正文 / 自媒体稿**：{口语化讲解段落 · 200-400 字 · 直接念}
>
> **核心要点**（AI 友好）：
> - 要点 1
> - 要点 2
> - 要点 3
>
> **配图**：[slides/slide-1.png](slides/slide-1.png)

---

## 第 2 章 · {章节名}
...
```

**md 的 3 作用**：

| 场景 | 怎么用 |
|---|---|
| **直接发公众号** | 整篇 md 复制粘贴 = 公众号长文 |
| **当自媒体讲解稿** | 念导语 + 每章正文段（口语化）= 视频 / 直播口播稿 |
| **AI 阅读使用** | 顶部"核心要点"列表 + 每章"核心要点"块 = LLM 直接消化 |

## 📊 锦绣 vs 3F Content 对比

| 维度 | 3F Content | 锦绣 |
|---|---|---|
| **服务对象** | AI | 人 |
| **输出形式** | .md / .pptx / .html | 2 封面 + 8-12 讲解图 + 1 md |
| **平台** | 通用 | creator 自决定（不限平台）|
| **创建时机** | 必须（提交前）| **必须（提交前自动生成）** |
| **可被 AI 消费** | ✅ | ❌（视觉是给人的） |
| **可被人消费** | ⚠️（可读但不传播）| ✅（专为传播设计）|

**3F Content + 锦绣 = 完整闭环**：
- 3F Content = 数据层（AI 消费）
- 锦绣 = 传播层（人消费）
- 两个一起 = 知识既被 AI 消化又被人传播

## 🛠️ 实际工作流（v3.1 推荐）

```
1. 用户写 3F Content（content.md + 9 张图 + PPTX + HTML）   ← 数据层
   ↓
2. skill-creator 跑                                       ← 自动化
   ├─ 1 张横屏封面
   ├─ 1 张竖屏封面
   ├─ 8-12 张讲解图（从 content.md 提取）
   └─ 1 份融合 md（导语 + 核心要点 + 每章正文 + 配图）
   ↓
3. creator 调优视觉（30 分钟）                              ← 人机协作
   ↓
4. 跑 check-3f.py 验证                                     ← 自动化校验
   ↓
5. 提 PR → GitHub Actions 自动跑 → merge                 ← 开发者PR共建
   ↓
6. creator 拿到完整锦绣素材 → 自由决定发哪（朋友圈/小红书/抖音/...）
```

**关键**：
- 步骤 1-2 = 机器做（80% 自动化）
- 步骤 3 = 人做（20% 调优）
- 步骤 4-5 = 工具做（100% 自动化）
- **步骤 6 = creator 决定发哪**（不锁死平台）

## 💯 设计原则

> **知识的价值 = 创作质量 × 传播质量**。
>
> 创作质量 = 3F Content（数据 + AI 友好）。
> 传播质量 = 锦绣（视觉 + 多形式）。
> 传播到哪 = **creator 决定，不锁死平台**。
>
> 范式只规定"**形式**"（横/竖/讲解图/md），不规定"**平台**"（朋友圈/小红书/抖音/...）。
> 这样新平台出现不需要改范式，creator 拿到素材自己适配。

### v3.3 项目哲学重塑

> **清晰 > 速度 · 让人看得懂 > 快速生成 SOP**

**任何工具 / 范式 / 自动化**的设计都应该服务于"**讲清楚**"，而不是"**快**"。

- skill-creator 工具：辅助 creator **多花几分钟讲清楚**，不是"省时间"
- 锦绣：花 5 分钟生成视觉素材 = 让人**真正看懂**，不是"自动化产出"
- check-3f.py：确保**讲清楚了**，不是"快速通过"

**多花 5 分钟讲清楚 = 100 倍可懂性提升** = 知识被真正使用 = 项目真正价值。
