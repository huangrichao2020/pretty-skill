- **标题**：Git 沙箱求生术

  - 公开仓 / 私有仓各有正确的拉取姿势
  - 协作前先确认"不落后"，别死等 SSH

- **金句**：卡住不是你的问题，是路径的问题

## P1 · 现象 / 痛点

- **标题**：SSH fetch 卡死 120 秒
- **副标**：git fetch 走 SSH 零输出、RC=124，像死机
- **章节类型**：现象 / 痛点
- **核心主张**：在沙箱里 `git fetch` 走 SSH 会静默卡死，不是慢，是 stall
- **认知锚点**：「3 大翻车现场」—— SSH 拒/代理死/token 401
- **关键要点**：
  - 现象：120s 零输出，退出码 124（timeout）
  - 不是偶发：每次 fetch 都卡，pull / rebase 前的 fetch 也卡
  - 第一次遇到会误判为"网络不通 / 认证失败"
- **数据 / 数字**：120s · RC=124
- **金句**：沉默的卡死比报错的失败更骗人

---

## P2 · 诊断 / 排除

- **标题**：诊断：不是认证问题
- **副标**：ssh -T / ls-remote / push 全正常，唯独 fetch 卡
- **章节类型**：诊断 / 排除
- **核心主张**：先排除认证，再下结论——别一卡就重配 SSH key
- **认知锚点**：「4 步诊断排除表」—— ping/curl/ssh/gh 4 步
- **关键要点**：
  - `ssh -T git@github.com` 正常（认证 OK）
  - `git ls-remote` 正常（能连上远端）
  - `git push` 正常（上行 OK）
  - 唯独 `git fetch`（下行 upload-pack）卡死
- **数据 / 数字**：3 项正常 / 1 项卡死
- **金句**：对了一半的排查，比没排查更危险

---

## P3 · 根因 / 原理

- **标题**：根因：upload-pack 路径 stall
- **副标**：SSH 协议栈在 fetch 阶段 stall，与权限无关
- **章节类型**：根因 / 原理
- **核心主张**：这是 SSH 协议 fetch 路径的 stall，不是 GitHub 拒绝你
- **认知锚点**：「5 大根因地图」—— 网络/认证/权限/路径/协议
- **关键要点**：
  - 卡死点在 upload-pack 协商阶段，全程零输出
  - 与 SSH key / 权限 / 2FA 无关（否则 push 也失败）
  - 是沙箱网络环境对该协议路径的特殊限制
- **数据 / 数字**：stall 在 upload-pack
- **金句**：知道不是什么，比知道是什么更省时间

---

## P4 · 解法 / 操作

- **标题**：解法：HTTPS 智能 HTTP fetch
- **副标**：公开仓免认证 https:// 拉取，秒回 8MB/s
- **章节类型**：解法 / 操作
- **核心主张**：公开仓用 HTTPS 智能 HTTP 协议拉取，瞬时成功
- **认知锚点**：「6 类解法操作手册」—— 重试/换协议/换路径/换工具
- **关键要点**：
  - 命令：`git fetch https://github.com/<user>/<repo>.git <branch>:<refs/remotes/origin/<branch>>`
  - 免认证：公开仓走智能 HTTP 不需要 token
  - 实测：8MB/s 秒回，用来确认"不落后"再 rebase
  - 速度远胜 SSH 死等 120s
- **数据 / 数字**：8MB/s · 秒回
- **金句**：换条路，比修这条路快

---

## P5 · 进阶 / 纪律

- **标题**：跨仓 PAT 复用 + 协作纪律
- **副标**：PAT 覆盖全仓 · rebase 方向 · 真实退出码
- **章节类型**：进阶 / 纪律
- **核心主张**：私有仓用 PAT；跨仓复用同一 PAT；协作遵守两条纪律
- **认知锚点**：「5 条铁律纪律」—— 不主动 commit/amend 警告
- **关键要点**：
  - info-hub 的 PAT（ghp_xxx）对 huangrichao2020 名下所有仓（含 knowhub）都有效
  - 私有仓 fetch：`git fetch https://<PAT>@github.com/...git`
  - rebase 方向：`--ours`=目标分支（新真相）、`--theirs`=正在重放的旧提交
  - 校验真实退出码，别被 `| grep` 的退出码掩盖
- **数据 / 数字**：1 个 PAT · 全覆盖
- **金句**：方向搞反，合并就炸

## P6 · 收束 / 速查

- **标题**：速查卡：一页救命
- **副标**：4 条命令 + 3 条纪律，贴墙备查
- **章节类型**：收束 / 速查
- **核心主张**：把四条命令和三句纪律存进肌肉记忆
- **认知锚点**：「速查表 + 紧急按钮」—— 1 页速查 + 紧急恢复
- **关键要点**：
  - 公开仓：`git fetch https://github.com/u/r.git main:refs/remotes/origin/main`
  - 私有仓：`git fetch https://PAT@github.com/u/r.git ...`
  - push 仍走 SSH：`git push`（已认证 huangrichao2020）
  - 纪律：先 fetch 确认不落后 → 再 rebase/push；看真实退出码；不硬造
- **数据 / 数字**：4 命令 / 3 纪律
- **金句**：能秒回的，不要死等
