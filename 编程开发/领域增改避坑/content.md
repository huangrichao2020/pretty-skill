- **金句**：改名字容易，改一致性难

  - 这些 domain 不在英文 PRESET 里 → `check_manifest` 一直 EXIT=1
  - 管道 `| grep` 的退出码掩盖了真实失败，肉眼看不出
- **数据 / 数字**：3 个 case · 长期失败
- **金句**：被掩盖的错误，比错误本身更贵

## P2 · 根因 / 原理

- **标题**：根因：双脚本硬编码 PRESET
- **副标**：check-3f.py 与 create.py 各写一份 PRESET_DOMAINS
- **章节类型**：根因 / 原理
- **核心主张**：PRESET_DOMAINS 在 check-3f.py 和 create.py 里各硬编码一份
- **认知锚点**：「check-3f 守门员」—— 守门员检查 3 阶段
- **关键要点**：
  - check-3f.py 的 PRESET_DOMAINS 是校验口径（领域合法性）
  - create.py 的 PRESET_DOMAINS 是脚手架口径（新建 case 时选领域）
  - 只改一处 → 要么校验拦你，要么脚手架生成错领域
  - manifest.domain 必须等于 PRESET 里的 key（中文）
- **数据 / 数字**：2 处硬编码
- **金句**：两份真相，必有一份过时

- **章节类型**：解法 / 操作

- **金句**：改一处，验一次，别攒着

## P4 · 进阶 / 坑

- **标题**：中文正则坑：\b 对中文失效
- **副标**：ASCII 词边界把中文当单词字符，改用正则
- **章节类型**：进阶 / 坑
- **核心主张**：批量替换文档里的领域名，不能用 ASCII `\b` 词边界
- **认知锚点**：「3 类高级坑」—— 中文化/路径/manifest 3 坑
- **关键要点**：
  - Python re 的 `\b` 按 ASCII 词边界，中文不是"单词字符" → 匹配错位
  - 后果：部分中文领域名替换漏掉或误伤英文词
  - 改用显式分隔（前后是空白 / 标点）的写法，而非 `\b`
  - 排除 `.git` / `.workbuddy` / 历史 dream-log / 已手改脚本 / manifest
- **数据 / 数字**：36 个文档受影响
- **金句**：工具按西文设计，中文要自己兜底
