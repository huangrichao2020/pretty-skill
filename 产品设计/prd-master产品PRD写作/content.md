## P0 · 封面

- **核心主张**：PRD 不是需求清单，是用证据支撑的决策文档
- **认知锚点**：「先 evidence 后结构」— 借鉴 dashiai-ppt / CyberPPT / wechat-delivery 同源思路
- **疗效**：写一篇功能 PRD，从 5h 草草列功能 → 30 min 出可评审决策文档
- **金句**：写完就能用，评审批量 ↓ 50%

---

## P1 · 8 步工作流

- **标题**：8 步工作流（不可跳）
- **副标**：诊断 → 提问 → 选型 → 写 → 4 句话 → 证据 → 对抗 → 自评 → 导出
- **章节类型**：流程
- **核心主张**：跳过任何 1 步 = 写完也没人用
- **关键要点**：
  - ① 诊断与路由：识别项目/产品/阶段/证据成熟度/AI 参与度
  - ② 关键提问：≤3 个，每轮问最影响决策的
  - ③ 选文档类型：7 路由选 1，不硬套功能 PRD 模板
  - ④ 写给读者决策：8 段框架（强制段 + 变化段）
  - ⑤ 首版 4 句话：问题/动作/效果/下一步放最前
  - 5.5 证据追踪：每条 evidence 必有落点（接口/状态/夹具/事件/负责人）
  - ⑥ 对抗审查：context-isolated，自己审自己 = 没审
  - ⑦ 路由自评：9 维硬卡 + 路由专项门槛
  - ⑧ 规范化导出：保留 md 源，再走 connector
- **数据/数字**：8 步 + 1 步 5.5 = 9 节点，5 行边界必填
- **金句**：跳过任何 1 步 = 写完也没人用

## P2 · 需求判断卡

- **标题**：需求判断卡（首步先 evidence）
- **副标**：5 字段 · 没填就别写 PRD
- **章节类型**：方法
- **核心主张**：没判断就写 PRD = 写完也没人用
- **关键要点**：
  - 字段 1：推荐文档类型（探索 Brief / 0→1 策略 / 功能 PRD / 实验 / API / 迁移 / 运营 / AI 模块）
  - 字段 2：当前阶段与证据成熟度（假设 / 部分证据 / 验证证据）
  - 字段 3：风险等级 + AI 影响（可逆 / 谨慎 / 难逆 / 无 AI / AI 辅助 / AI 核心）
  - 字段 4：为什么采用这个文档（替代方案 + 选择理由）
  - 字段 5：必须先确认的未知项（不知道 = 写下来 = 不要装作知道）
- **数据/数字**：5 字段 / 0 字段可填"待定"
- **金句**：PRD 写完没人用 = 判断卡没写

## P3 · 8 段通用框架

- **标题**：8 段通用框架（缺段 = 文档不合格）
- **副标**：强制段 1/2/3/4/7/8 + 变化段 5/6
- **章节类型**：框架
- **核心主张**：8 段强制，任何文档类型都要有
- **关键要点**：
  - ① 决策摘要：要解决的问题/决策/为什么现在做/预期变化
  - ② 用户、场景与证据：目标用户/当前做法/已知证据/关键假设
  - ③ 竞品与替代方案研究：比较对象/比较维度/可借鉴之处/映射到决策
  - ④ 目标、范围与约束：目标与成功标准/包含什么/不包含什么/取舍
  - ⑤ 核心方案（按路由变）：用户旅程/工作流/规则/状态/失败处理/UI 交接
  - ⑥ 推进与验证方式：依赖/验收/分阶段/灰度/监控
  - ⑦ 风险、依赖与开放决策：风险+缓解/外部依赖/仍待拍板
  - ⑧ 埋点与指标：功能完成度（功能是否跑通）+ 产品与用户价值（是否值得保留）
- **数据/数字**：8 段，2 段变化（5/6 按路由变）
- **金句**：缺任何 1 段 = 写完也得回炉

---

## P4 · 7 种文档路由

- **标题**：7 种文档路由（选错 = 文档走偏）
- **副标**：按决策类型选 1 · H AI 模块可与 A-G 组合
- **章节类型**：分类
- **核心主张**：「PRD」≠ 功能 PRD — 可能是探索 Brief 或策略备忘录
- **关键要点**：
  - A 探索 Brief：问题/机会未验证 → 段 5 问题框定 + 段 6 推进/暂停/停止
  - B 0→1 策略：团队需要方向 → 段 5 目标用户+JTBD+楔点+差异化 / 段 6 阶段路线+决策门
  - C 功能 PRD：用户价值/范围清晰 → 段 5 用户旅程+工作流+UI 交接 / 段 6 依赖+验收+实验
  - D 实验方案：验证改动是否带来结果 → 段 5 假设+人群+自变量+对照 / 段 6 观察窗+决策规则
  - E 平台 API：别系统消费 → 段 5 能力边界+调用方+输入输出+鉴权 / 段 6 版本+兼容性
  - F 改版/迁移：改既有行为 → 段 5 受影响用户+前后行为+兼容 / 段 6 灰度+回滚
  - G 上线运营：已发布能力运行 → 段 5 发布范围+监控+响应+手工 SOP / 段 6 沟通+复盘
  - H AI 模块（可与 A-G 组合）：AI 是用户可见或核心 → 段 5 边界+数据+权限+人类 fallback / 段 6 评测+监控+隐私
- **数据/数字**：7 路由 + 1 AI 模块
- **金句**：选错路由 = 文档走偏

## P5 · 强制边界条件块

- **标题**：强制边界条件块（5 行必填）
- **副标**：缺行 = 文档自评不通过
- **章节类型**：方法
- **核心主张**：边界条件 = 文档可执行性的硬卡
- **关键要点**：
  - 行 1：适用性 / 范围（谁能用 + 什么不能）
  - 行 2：输入 / 状态（空 / 错 / 过期 / 重复 / 不安全）
  - 行 3：失败 / 恢复（超时 / 权限错 / 部分成功 / 重试 / 取消 / 回滚）
  - 行 4：兼容性 / 容量（不支持的版本 / 资源限制 / 降级）
  - 行 5：信任 / 隐私（敏感数据 / 不安全动作 / 用户可见完成信号）
  - 不适用：写 N/A + 原因，不能空着
- **数据/数字**：5 行必填 / 0 行可空
- **金句**：没边界条件 = 写完也得返工

---

## P6 · 首版 4 句话

- **标题**：首版 4 句话（4 句话放最前）
- **副标**：问题/动作/效果/下一步
- **章节类型**：方法
- **核心主张**：读者不用从背景推结论
- **关键要点**：
  - 句 1：问题（一句话 · 用用户可观察结果 + 背后证据）
  - 句 2：核心动作（一句话 · 最小产品/工作流改动 = 移除主要障碍）
  - 句 3：预期效果（一句话 · 用户能完成 + 团队能验证）
  - 句 4：下一步决策（一句话 · 评审者批准/拒绝/验证什么）
  - 放在文档最前，不是最后
  - 写完初稿前必过这 4 句
- **数据/数字**：4 句话 / 0 句可省
- **金句**：长篇背景后才出结论 = 写到一半走偏

---

## P7 · 对抗式审查

- **标题**：对抗式审查 context-isolated
- **副标**：自己审自己 = 没审
- **章节类型**：流程
- **核心主张**：reviewer 在作者同一个 session 跑 = 不算隔离
- **关键要点**：
  - 5 步流程：①启动新 agent ②只传草稿+证据+假设 ③不可传作者隐藏推理 ④需可验证隔离证明 ⑤不通过走审批门
  - 4 审查维度：产品决策 / 漏洞失败路径 / 可行性 / 证据价值
  - Finding 6 字段：Severity / Location / Finding / Evidence / Consequence / Recommendation
  - 作者必须处理 Blocker + High；Medium/Low 改或显式记录
  - reviewer 不改文档，只给 findings
  - "用了一个新 agent" 文本声明 = 不算
- **数据/数字**：5 步流程 + 4 维度 + 6 finding 字段
- **金句**：自己审自己 = 没审

## P8 · 工具分工

- **标题**：工具分工（先 evidence 后结构）
- **副标**：prd-master 是这个思路在产品文档上的最严格实现
- **章节类型**：对比
- **核心主张**：4 个工具共享同源思路
- **关键要点**：
  - 普通 PRD 模板：需求清单 / 不强调证据 / 写完没人用
  - prd-master：决策文档 + 对抗审查 / 8 段框架 / 7 路由 / 强制边界
  - CyberPPT：PPT 三段式 / slides[].evidence 字段
  - dashiai-ppt：HTML PPT / slides[].evidence 字段
  - wechat-delivery 8 维 rubric：公众号 / sections[].evidence 字段
  - 共同点：先 evidence 后结构 / 不再写需求堆砌
- **数据/数字**：4 个工具共享 1 思路
- **金句**：共同点 = 先 evidence 后结构
