# prd-master · 产品 PRD 写作

## 一句话定位

PRD 不是需求清单，是**用证据支撑的决策文档**。**先过证据关，再过结构关，最后过对抗审查关**。

## 8 步工作流（强制 · 跳步 = 出问题）

1. **诊断与路由** → 2. **关键提问**（≤3 个）→ 3. **选文档类型** → 4. **写给读者决策** → 5. **首版 4 句话** → 5.5 **证据追踪** → 6. **对抗审查** → 7. **路由自评** → 8. **规范化导出**

详见 `content.md` 第 1 节。

## 适用 / 不适用

**适用**：
- 写功能 PRD / 0→1 策略 / 改版迁移 / 平台 API / 实验方案 / 上线运营
- 任何"先 evidence 后结构"的产品文档场景

**不适用**：
- 简单 issue / bug 报告
- 1-2 句话能讲完的小决策
- 还没想清楚要不要做的方向（先探索 Brief）
- 单纯的发布会讲稿
