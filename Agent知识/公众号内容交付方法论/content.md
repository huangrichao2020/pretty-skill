## P1 · 钩子 · 凌晨 3 点的公众号作者

凌晨 3 点，我盯着公众号后台发呆。

那天我写了第 18 篇草稿，从「选题」到「正文」花了 2 小时。但「发布」花了我 5 小时——配图、封面、缩进、字号、段间距、CTA 按钮位置。改完发现图又被微信压糊了，重新出一遍。

这是公众号作者的真实痛：**写完 ≠ 发出去**。你写完了，但你没「交付」。因为公众号编辑器是最后一道坎：CSS 不听话、图片要重新传、字号配色每次都重置、动效丢失。

我做 pretty-skills 不是为了「做工具」，是因为我自己就是那个凌晨 3 点的人。

---

## P2 · 总纲 · 5 步交付流程

读完这篇文章，你能：

1. 把「写完一篇公众号」从 10h 缩短到 30min
2. 用「7 段黄金模板」写出读者愿意看完的长文
3. 用「桌面 8 文件」让用户在 30 秒内粘贴发布

5 步流程：调研 → 写 → 出图 → 桌面交付 → 用户粘贴。

---

## P3 · Step 1 调研需求（30 秒）

按硬规则「出最终方案前先问 1 个关键问题」：

> **「这篇文章的读者是谁 + 你想让他们看完拿走什么？」**

不要问「你想写什么话题」「字数多少」「风格」—— 这些会被默认值吞。

调研只问 1 个问题，30 秒搞定。

---

## P4 · Step 2 写文章（30 min · 7 段黄金模板）

公众号正文 = 标题 + 7 段正文。

**标题（30 字以内）**：痛 + 量化 + 场景。3 filter 自检：疗效、量化、场景。

**钩子（80-150 字 · 第一段）**：凌晨 3 点的故事 / 一次失败 / 一个反常识。决定读者是否继续读。

**总纲（80-120 字 · 第二段）**：1 句话讲完「读完能拿走什么」。用 ① ② ③ 列 3 个具体能力。

**解法（1500-2000 字 · 主体）**：3 个方法各 500 字 + 配图。每方法都要有步骤（不是 4 字缩略）、配图、反例。

**疗效（300-500 字）**：量化数字（X 倍速 / Y 元 / Z 小时）+ 3 filter 自检。

**CTA（50-80 字）**：单一行动（转发 / 评论 / 关注，只能选 1）。

**写在最后（30-50 字）**：可截图发朋友圈 · 1 句话能独立传播。**用「写在最后」自然过渡，不用「金句」标签**。

---

## P5 · Step 3 出图（10 min · matrix MCP 5 张图）

5 张图：1 封面 + 4 配图。风格默认锁定「手绘马卡龙」。

**v3.21 硬规则**：
- 少字（≤ 1 行中文）
- 留白 ≥ 30% 面积
- 大字（深棕手写体）
- 一图一概念
- 中心构图，无装饰边框
- 封面按 **2.35:1 + 1:1 兼容规则**（主体居中靠下 + 顶部 30% 留标题）

成本：5 张图 · 2.5-3.3 MB/张 · 总成本 ~ 5 元（vs Midjourney 50 元）。用 MiniMax Token plan 套餐 49 元起步。

---

## P6 · Step 4 桌面文件夹交付（10 秒）

Mavis 跑 `scripts/build_delivery.py` 自动建桌面文件夹。

路径：`~/Desktop/公众号/<name>-<YYYY-MM-DD>/`，8 文件结构：

```
公众号-<name>-YYYY-MM-DD/
├── README.md             # 粘贴指南
├── 标题.txt              # 复制 → 输入框
├── 正文.txt              # 复制 → 富文本编辑器
├── 封面.png              # 上传 → 封面位
├── 配图1.png
├── 配图2.png
├── 配图3.png
└── 配图4.png
```

正文 `正文.txt` 里标好 4 个 `[P1]` `[P2]` `[P3]` `[P4]` 位置，让用户知道在哪里插入。

---

## P7 · Step 5 用户粘贴（30 秒）

用户的 5 个动作：

1. 复制 `标题.txt` → 输入标题框
2. 复制 `正文.txt` → 粘贴到富文本编辑器
3. 上传 `封面.png`（拖拽到封面位）
4. 按 README 标注位置插入 4 张配图
5. 点群发 / 发布

**总耗时**：30 min（Mavis 端） + 30 秒（用户端）。

## P8 · mavis browser 工具栈天花板（实测失败清单）

实测新版公众号编辑器（React 富文本，不是 iframe UEditor），`mavis browser` 工具栈有 6 类失败：

1. **`type` 工具**：只能打到 input/textarea；公众号正文编辑器是 `<div>` 非 typable
2. **`press_key Cmd+V`**：React 组件捕获不到系统级粘贴事件（不冒泡到 native listener）
3. **`set_file_input`**：公众号封面位不是 file input（是点击触发 modal）
4. **`click` 菜单/按钮**：编辑器菜单是 React 动态渲染，selector 改了页面就失效
5. **iframe 操作**：v3.18 后公众号编辑器不在 iframe 里
6. **截图 + 坐标点击**：每次页面渲染后坐标会偏移

**结论**：`mavis browser` 的价值是「填表/上传/读」等明确 file input 场景，**富文本编辑器不是它的战场**。这条路放弃，改为交付物到桌面。

## P9 · 反模式库（3 个必避坑）

### 反模式 1：关键 UI 流程被默认值吞掉

走「自动插入公众号」→ React 编辑器点不动 → 浪费 2 小时。

正确做法：影响最终产物的参数默认 = None，不传 → 弹 picker 或 fail-fast。

### 反模式 2：营销首页浪费 token

把同样内容同时套到营销首页、飞书贴、小红书 → 每改一次要在 3 个地方同步。

正确做法：单一交付物（桌面文件夹），用户自己分发。

### 反模式 3：picker 被默认吞

调研阶段曾试图做「风格 picker」让用户选 → picker 在自动化流程里被默认走了第一项。

正确做法：picker 只用在「用户明确要求做 PPT / 出图」的场景，写作流程里不弹。

省钱：

- 省 99%

提效：

- 现在：1 周发 5 篇，还能复盘上周爆款

## P11 · 触发词与自动化（怎么让工具主动执行）

5 个触发词 / 0 询问 / 30 秒识别：

- 「写公众号」 → 自动走 5 步交付流程
- 「公众号文章」 → 同上
- 「（自己的公众号名）」 → 用户公众号名 → 默认走公众号
- 「配公众号」 → 已有文章 + 配图 → 桌面文件夹交付
- 「公众号配图」 → 只出配图不写文章

触发词让流程变成「不需要问的对话」。

## P12 · 收束（4 步开始 + 12 条自检）

**4 步开始**：

第 1 步：装 pretty-skills（`curl -fsSL ... | bash`）
第 2 步：说「写公众号」+ 选题 + 读者 + 拿走什么
第 3 步：等 Mavis 跑完 30 min，桌面文件夹出来
第 4 步：用户 30 秒粘贴发布

**12 条自检清单**：

- [ ] 标题过 3 filter（疗效 / 量化 / 场景）
- [ ] 钩子有具体时间/数字/失败
- [ ] 总纲用 ① ② ③ 列 3 个能力
- [ ] 解法每个步骤都有具体动作（不是 4 字缩略）
- [ ] 疗效用「省时/省钱/提质」简洁格式
- [ ] CTA 只有 1 个
- [ ] 收束用「写在最后」段落，不用「金句」标签
- [ ] 封面图按 2.35:1 + 1:1 兼容（主体居中靠下）
- [ ] 5 张图都是 2K（≥ 1MB）
- [ ] 桌面文件夹 8 文件齐全
- [ ] README 粘贴指南清楚
- [ ] 用户操作时间 ≤ 30 秒

## 写在最后

公众号不是写作，是交付。

你写完了不算完，发出去才算。

桌面文件夹是最朴素的 GitHub Pages：把最终产物整整齐齐交付到用户手边，30 秒粘贴完事。

---

## 适用场景

- 个人 / 公司公众号周更
- 行业号深度长文（5000 字 + 5 张配图）
- 内容创作者想批量生产（一次写 3 篇，3 篇都用桌面交付）

## 不适用

- 实时新闻（公众号发布节奏跟不上）
- 视频内容（公众号视频是另一套范式）
- 直播（公众号没有原生直播位）
