## P6 · Step 4 桌面文件夹交付（8 个文件结构）

- **标题**：Step 4 桌面文件夹交付 · 8 个文件 + 一份 README
- **副标**：`~/Desktop/公众号/<文章名>-<日期>/` 标准结构
- **章节类型**：核心解法
- **核心主张**：桌面文件夹是「按文件思考」的最佳实践 — 每个文件 1 个职责
- **关键要点**：
  - `00-README.txt` — 操作流程指南（粘贴顺序 + 配图位置对照）
  - `01-标题.txt` — 标题纯文本（公众号限制 64 字）
  - `02-正文.md` — 正文去 markdown 纯文本（Cmd+A + Cmd+V 直接用）
  - `03-封面-P0.png` — 头条封面图（封面区用）
  - `04-配图-N-<主题>-P<n>.png` — 文中配图（按章节顺序命名 P1/P2/P3/P4）
  - 命名规范 · 按时间倒序排序（00 在前 → 04 在后）
- **数据 / 数字**：8 文件 · 文件大小 100KB-6MB · 总耗时 3 分钟
- **金句**：桌面文件夹是最朴素的 GitHub Pages。
- **童趣图标**：📁 桌面文件夹展开

## P8 · mavis browser 工具栈天花板（实测失败清单）

- **标题**：mavis browser 自动化公众号编辑器的 6 类失败
- **副标**：别再浪费时间试自动化插入
- **章节类型**：深化
- **核心主张**：mavis browser 接管真实 Chrome 对**复杂富文本编辑器**完全不够
- **关键要点**：
  - ❌ type 到 `<div>` → 「Element is not typable」
  - ❌ type 到 contenteditable React 组件 → 组件内部 state 不更新
  - ❌ press_key Cmd+V → focus 没在 contenteditable 内，没生效
  - ❌ set_file_input 触发了 file dialog 但**公众号素材库上传没真正完成**（count=0 但 names 有）
  - ❌ click li 菜单 → 下拉菜单不消失（dom 状态没更新）
  - ❌ screenshot 工具需要 user gesture 触发（activeTab permission）
  - ✅ 唯一成功：navigate / query/snapshot / 简单 click / set_file_input 触达 file input
- **数据 / 数字**：6 类失败 · 8 类工具 · 实测 30+ 次
- **金句**：工具能写完文章，但工具发不进公众号（编辑器是另一道坎）。
- **童趣图标**：⚠️ 失败警告

## 🎓 适用场景

- 个人 / 公司公众号周更
- 行业号深度长文（5000 字 + 5 张配图）
- 内容创作者想批量生产（一次写 3 篇，3 篇都用桌面交付）

## ❌ 不适用

- 实时新闻（公众号发布节奏跟不上）
- 视频内容（公众号视频是另一套范式）
- 直播（公众号没有原生直播位）
