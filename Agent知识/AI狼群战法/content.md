## P3 · Part 1 — Context 三层办公室

- **章节类型**：核心解法（STAR-C 案例 + 第一层方法论）
- **核心主张**：给 AI 一个能自己做事的三层办公室
- **三层结构**：
  - **L1 静态知识库「入职手册」**（浅蓝 #BDE0FE）：产品架构文档 / 代码规范 / 历史决策记录 / 用户画像
  - **L2 动态工作空间「当前任务看板」**（薄荷绿 #C7F0BD）：会议纪要 / 需求优先级 / 代码变更记录 / 未关闭工单
  - **L3 工具与权限「能干 / 不能干」**（奶黄 #FFE5A5）：可读可写测试可查日志 / 不可部署生产不可改用户数据
- **数据 / 数字**：3 层
- **金句**：「传统方式是'教 AI 怎么做'，上下文工程是'给 AI 一个能自己做事的环境'。」
- **童趣图标**：三层立体方块屋 / 楼梯 / 书本 / 看板 / 工具箱

## P4 · Part 2 — Observation 闭环

- **章节类型**：核心解法（STAR-C 案例 + 第二层方法论）
- **核心主张**：即时反馈 + 定期复盘 = 成长闭环
- **即时反馈 Instant Feedback**（桃粉 #FFB5BA）：
  - 工程师审查代码：合并还是退回？
  - 产品经理看方案：采纳还是修改？
  - 测试验证用例：覆盖全不全？
- **定期复盘 Weekly Review**（淡紫 #D8BFD8）：
  - 任务回顾：本周成功率多少？
  - 错误分析：哪些反复出错？
  - 经验沉淀：哪些场景处理得比预期好？
- **数据 / 数字**：Agent 系统天然是非确定性，95% 表现出色但 5% 令人尴尬 → Observation 要解决的就是那 5%
- **金句**：「Agent 在 95% 情况下表现出色，Observation 要解决的就是那个 5%」
- **童趣图标**：循环箭头 / 对号 / 错号 / 眼睛 / 放大镜

## P5 · Part 2 深化 — Memory Evolution

- **章节类型**：深化 / 双案例对照 + 金句嵌
- **核心主张**：从人类反馈中提炼规则，让 Agent 自主进化
- **正向反馈 Positive**（薄荷绿 #C7F0BD）：
  - 销售团队用 Agent 生成跟进邮件，客户回复率高
  - → 标记优秀案例
  - → Memory Update：「这种语气和结构的邮件转化率高」
- **负向反馈 Negative**（奶黄 #FFE5A5）：
  - 研发发现 Agent 生成的代码有性能问题
  - → 修改并提交
  - → Agent 捕获修改差异
  - → Memory Update：「处理大规模并发时，避免使用低效循环」
- **数据 / 数字**：—
- **金句**：「团队的共同目标是：养好这个 Agent。」
- **童趣图标**：信封 + 笑脸 + 星标 / 齿轮 + 警告标 + 修复扳手 / 底部金句横幅

## P6 · Part 3 — Human Role 4 角色升级

- **章节类型**：角色升级 / "X 不是 Y，是 Z" 句式
- **核心主张**：默认所有执行工作由 AI 完成，但人的角色升级了
- **4 个角色升级**：
  - **产品经理 → Prototyper 原型师**：从写 PRD 到 "产出大量创意和原型，定义目标和验收标准"
  - **工程师 → Builder 构建师**：从写代码 到 "将原型转化为生产级产品，构建 Context 和 Agent 基础设施"
  - **测试 → Evaluator 评估者**：从手动测 到 "设计测试策略和评估 Agent 输出，优化系统反馈机制"
  - **管理者 → Trainer 训练者**：从管人 到 "优化人机协作，治理团队上下文，对齐 AI 系统与公司目标"
- **新人才**：Context Provider / Fast Learner / Hands-on Builder
- **数据 / 数字**：4 角色
- **金句**：「不是 AI 替代你，是会用 AI 的同行替代你。」
- **童趣图标**：图纸 / 工具箱 / 对勾 / 指挥棒
