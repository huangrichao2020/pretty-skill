## P1 · 痛点切入

- **标题**：为什么"扫盲一个领域"90% 翻车
- **副标**：堆料 vs 结构化
- **章节类型**：核心解法
- **核心主张**：90% 领域入门翻车是因为**堆料**（收藏夹满 = 没入门）——本 skill 用 5 阶段流水线 + 5 道质量门强行逼你"能讲清"
- **认知锚点**：「4 大扫盲翻车坑」

```text
坑 1：堆料不消化
  表现：收藏夹满 / 看过 N 篇文章 / 讲不出 3 句话
  解决：5 阶段流水线 + 并行调研 + 强制写作

坑 2：无地图
  表现：东看一篇西看一篇，没知识地图
  解决：阶段 1 调研 → 阶段 2 写 PROJECT.md（章节大纲 + 调研索引）

坑 3：单人单打
  表现：自己一个人写，超时 + 质量不稳
  解决：多 agent 并行（6-10 维度调研 + 多 agent 写作 + 3 审校 agent）

坑 4：事实失真
  表现：作者知识库错误 → 反复传播（信息茧房）
  解决：第 4 道门独立事实核查（强制 WebSearch + 独立怀疑者）
```

- **数据 / 数字**：4 翻车坑 / 90% 堆料不消化
- **金句**：能讲清 = 入门

## P2 · 5 阶段流水线

- **标题**：调研 30% → 规划 10% → 写作 30% → 审校 20% → 构建 10%
- **副标**：30-60 天 5 阶段走完
- **章节类型**：核心解法
- **核心主张**：5 阶段流水线 = 标准 30-60 天 / 1 本橙皮书 / 全流程 SOP
- **认知锚点**：「5 阶段 SOP」

```text
阶段 1 调研（30%）
  做什么：6-10 维度并行 background agent
  核心产物：research/*.md（每个维度 1 文件）
  关键：并行化（6-10 个 agent 同时跑）

阶段 2 规划（10%）
  做什么：写 PROJECT.md
  核心产物：章节大纲 + 调研索引 + agent 分工
  关键：先给知识地图再填料

阶段 3 写作（30%）
  做什么：多 agent 并行写作
  核心产物：fragments/*.html（每个章节 1 个 HTML）
  关键：每个 agent 先学风格 + 读样本

阶段 4 三审三校（20%）
  做什么：5 个 agent 并发审校（5 道门）
  核心产物：修复后的 fragments
  关键：第 4 道门独立（不能用写作者的知识库）

阶段 5 构建（10%）
  做什么：PDF / DOCX / EPUB 3 套 pipeline
  核心产物：output/*.pdf / *.docx / *.epub
  关键：Penguin 三段式封面（统一视觉）
```

- **关键要点**：
  - 5 阶段不是"顺序串行"，是"并行 + 串行混合"：调研并行、写作并行、审校并行
  - 阶段 2 规划 = 1-2 天**最关键**——没规划 = 后面全乱
  - 阶段 4 审校 = **最贵**（5 agent 并发 + 独立事实核查）
  - 阶段 5 构建 = 自动化（build.js / build-pdf.js）
- **数据 / 数字**：5 阶段 / 时间占比 30/10/30/20/10 / 6-10 并行 agent
- **金句**：规划 = 后面 80% 的效率

## P3 · 5 道质量门

- **标题**：内容 / 风格 / 细节 / 事实（独立）/ 一致性
- **副标**：第 4 道门必须独立 WebSearch
- **章节类型**：核心解法
- **核心主张**：5 道质量门 = 5 个不同角度的审校，第 4 道门（事实核查）必须**独立 WebSearch**，不能依赖模型记忆（信息茧房）
- **认知锚点**：「5 道质量门」

```text
门 1 内容/事实审校
  审什么：时间线 / 工具对比 / 数据 / 人物归因
  谁审：内容审校 agent

门 2 风格审校
  审什么：去 AI 腔 / 加作者语感
  谁审：风格审校 agent

门 3 细节打磨
  审什么：句长 15-25 字 / 段 3-5 行 / 小标题 300-500 字一个
  谁审：细节审校 agent

门 4 事实核查（独立怀疑者）★关键★
  审什么：质疑"前提成立吗" / 修数字更要修论点
  谁审：独立 agent（强制 WebSearch，不能用模型记忆）
  关键：与门 1 独立——写作者和审校者共用知识库 = 错误在同一个信息茧房反复传播

门 5 全书一致性审查
  审什么：跨章节重复 / 观点冲突 / 术语不一致
  谁审：一致性审校 agent
```

- **关键要点**：
  - **5 道门全部并发审校** = 节省时间
  - **第 4 道门必须独立** = 不依赖作者 / 内容审校者的知识库
  - 论点比数字更容易错（事实核查不止查数字，要查论点）
  - 修复后的 fragments = 阶段 5 构建的输入
- **数据 / 数字**：5 道门 / 5 agent 并发 / 第 4 道门独立
- **金句**：事实核查独立 = 对抗信息茧房

## P4 · 4 底层原则

- **标题**：结构先行 / 并行化 / 真入门 = 能讲清 / 事实优先
- **副标**：5 阶段 + 5 门的底层
- **章节类型**：核心解法
- **核心主张**：4 底层原则 = 5 阶段流水线的灵魂——所有 SOP 都可以改，4 原则不能破
- **认知锚点**：「4 底层原则」

```text
原则 1 结构先行
  含义：先给知识地图再填料
  反例：一上来甩链接 / 甩名词
  正例：阶段 2 写 PROJECT.md 知识地图

原则 2 并行化
  含义：6-10 维度调研 + 多 agent 写作 + 3 审校 agent 并发
  反例：单人单写 / 串行审校
  正例：所有阶段能并行的都并行

原则 3 真入门 = 能讲清
  含义：强行逼你把领域讲清楚
  反例：收藏夹满 / 看过 N 篇文章 / 讲不出 3 句话
  正例：写作阶段逼你输出 = 倒逼输入

原则 4 事实优先于流畅
  含义：怀疑者独立核查一切事实声明
  反例：作者错误 → 审校者同样错 → 信息茧房
  正例：第 4 道门强制 WebSearch 查一手源
```

- **关键要点**：
  - 4 原则是"为什么 5 阶段 + 5 门能 work"的根本原因
  - 砍掉任何 1 原则 = 流水线会跑偏
  - 第 3 原则（真入门 = 能讲清）= 与其他扫盲方法最大区别
  - 第 4 原则（事实优先）= 抵抗 LLM 信息茧房的核心
- **数据 / 数字**：4 原则
- **金句**：能讲清 = 入门；能质疑 = 进阶
